# 記録s3 怪我ペイン追加 実装計画

> この計画は「今の最善の方針」であり、実装中に問題や改善案が出たら臨機応変に変更する。

## 背景・目的

トレーニング中に記録タブ（s3）を離れず怪我の履歴を参照できるようにする。

- **日付ビュー**：最近どこが痛んでいるか確認し、無理なトレーニングを避けるため
- **部位ビュー**：長く傷めている箇所を確認し、養生しながらトレーニングするため

## 実装の順序（重要）

**必ずこの順序で行うこと。**

1. **STEP 1**：怪我タブの表示修正（後述の「事前修正」参照）
2. **STEP 2**：s3怪我ペインの実装（STEP 1で確定したUI・CSSを流用）

STEP 1を先に行う理由：s3ペインはSTEP 1のコード・CSSを共通化して使うため、先に完成させておくと実装コストが下がる。

## 事前修正（STEP 1）：怪我タブの表示修正

### 部位ビューをアコーディオン方式に変更

**現状の問題**：部位タブで部位をタップすると別の詳細画面に遷移し、◀戻るボタンが必要になる。ペイン内の画面遷移として違和感がある。

**変更後**：部位タップで同じ場所にアコーディオン展開する（▼/▲で開閉）。戻るボタン不要。

```
【変更後の部位ビューイメージ】

右肩  3件 ▼         ← タップで展開
  2026/05/28  懸垂        メイン①  違和感
  2026/05/28  ベントオーバーロー  メイン②  違和感
  2026/05/15  懸垂        メイン①  違和感

左膝  2件 ▶         ← 閉じている状態
```

**変更箇所**：
- `app.js`：`renderInjurySite()` の描画ロジック（ドリルダウン → アコーディオン）
- `app.js`：`showInjurySiteDetail()` / `backFromInjurySiteDetail()` を削除
- `app.js`：`#btn-injury-site-back` のイベントリスナーを削除
- `index.html`：`#injury-site-detail-view`・`#btn-injury-site-back` を削除
- `style.css`：部位カードの展開スタイルを追加。ドリルダウン用スタイルを削除

### その他の表示調整

見づらい箇所は作業セッションで画面を見ながら確認・修正する（事前に一覧化しておくと効率的）。

### CSS設計の方針（STEP 1・STEP 2共通）

- `renderInjuryDate()` / `renderInjurySite()` を**コンテナ引数付き**に変更する
  - 例：`renderInjuryDate(container)` / `renderInjurySite(container)`
  - 怪我タブとs3ペインの両方から同じ関数を呼び出す
- CSSクラスは共通（一箇所修正すると両方に反映される）

## s3怪我ペインの仕様（STEP 2）

### レイアウト構成

#### PC 広い画面（≥ 約1600px）

3列構成で横並び表示。

```
┌─────────────────┬──────────────┬──────────────┐
│  左ペイン        │  中央ペイン   │  右ペイン     │
│  セット入力      │  種目履歴     │  怪我履歴     │
│  （550px固定）   │  （flex:1）   │  （flex:1）   │
└─────────────────┴──────────────┴──────────────┘
```

中央・右ペインは同じ幅（flex:1 を均等に）。`#app` の `max-width` を現状の1360px から拡張する（実装時に調整）。

#### PC 狭い画面（640px 〜 約1600px）

右エリアを「履歴」「怪我」タブで切り替え。2つのペインを同時表示しない。

```
┌─────────────────┬──────────────────────────────┐
│  左ペイン        │  [履歴] [怪我]               │
│  セット入力      │  ← タブで切り替え            │
│  （550px固定）   │                              │
└─────────────────┴──────────────────────────────┘
```

#### SP（〜 639px）

現行の履歴トグルに加えて怪我トグルを1つ追加。どちらも閉じた状態がデフォルト。開いたときに初回読み込みが走る。

```
[ セット入力エリア ]
[ HISTORY ▼ ]     ← 既存
[ INJURY  ▼ ]     ← 追加
```

### データ読み込み

| タイミング | 動作 |
|-----------|------|
| s3を開く（PC） | `getInjuryHistory` を自動で非同期呼び出し。左ペインの記録はブロックされない |
| SPで怪我トグルを開く（初回） | その時点で `getInjuryHistory` を呼び出し |
| 2種目目以降（PC） | `S.injuryRecords` にキャッシュ済みのため即表示 |
| セッション中 | キャッシュは再取得しない |

**読み込みのトリガー（実装指針）**：
- PC自動読み込みは `enterEx()` 内で呼び出す（現在 `loadS3Hist()` を呼んでいる箇所と同じ場所）
- 判定条件：`S.injuryRecords === null` のときだけ `loadInjuryHistory()` を呼ぶ。それ以外はスキップ
- SPは既存の履歴トグルと同じパターン（トグルを開いたとき、かつ未取得のときだけ呼ぶ）

**既存コードとの関係**：
- `S.injuryRecords` は既に `S` に定義済み（初期値 `null`）
- 怪我タブで先読みしていた場合（`S.injuryRecords !== null`）はs3でも即表示される
- 怪我タブを一度も開いていない場合のみ、s3入場時に初回取得が発生する

### 怪我ペイン内のUI

- **デフォルト表示**：日付ビュー
- **切り替え**：日付 / 部位 タブ（ペイン上部に配置）
- **日付ビュー**：日付カード → タップで展開 → 部位グループ → セット記録
- **部位ビュー**：部位アコーディオン（STEP 1で修正したUIと同一）
- **「もっと見る」**：将来実装。まず全件取得で進める

### 既存コードの流用方針

| 対象 | 流用方法 |
|------|---------|
| `renderInjuryDate(container)` | コンテナ引数付きに変更後、s3ペイン用コンテナを渡す |
| `renderInjurySite(container)` | 同上 |
| `loadInjuryHistory()` | `S.injuryRecords` がなければ呼ぶ共通関数として整理 |
| CSS（`.injury-rec-row` 等） | そのまま共通利用 |
